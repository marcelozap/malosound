# Native Studio Cockpit

`MaloSound-Studio.ps1` is the Windows-local entry point for the first practical
DAW workflow.

```powershell
.\Open-MaloSound-Studio.bat
```

It does not upload, post, release, or touch accounts. It only opens local files
and runs repo scripts.

## What It Controls

| Button | Action |
|---|---|
| Generate Stems | Writes a local utility stem kit under ignored `projects/` |
| Open Latest Kit | Opens the newest `STEMS.md` generated by the stem tool |
| Build DSP | Runs `scripts/build-dsp.ps1` |
| Open Projects | Opens the ignored local project folder |
| Stem Workflow | Opens `docs/STEM_GENERATION.md` |
| Plugin Plan | Opens `docs/ABLETON_PLUGIN_PLAN.md` |
| DSP Readme | Opens `dsp/README.md` |
| Start Here | Opens `docs/START_HERE.md` |
| Doctor | Runs fast local readiness checks |
| Open Library Note | Opens `LIBRARY_PATH.md` |
| Backup Notes | Opens `docs/BACKUP.md` |
| Repo Map | Opens `docs/REPO_MAP.md` |

## First Take Path

1. Enter the session name, BPM, bars, and beats per bar.
2. Click **Generate Stems**.
3. Click **Open Latest Kit**.
4. Import the WAVs into the DAW as separate tracks.
5. Record the vocal and movement pass against the timing stems.

The generated WAV files are not source. They stay under `projects/` or the XIV
Music Library and remain outside git.

## Preflight

Run the doctor before a recording session:

```powershell
.\Open-MaloSound-Doctor.bat
```

It checks the repo hook setup, toolchain, latest generated stem kit, music
library path, backup variable, and whether audio files are visible to git.
